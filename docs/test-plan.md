# Creator 筛选应用测试方案

验收按原题、用户新增需求及 implementation-plan.md 执行。全部自研前端、后端、共享及桌面 TS/TSX 的行覆盖率与分支覆盖率必须为 100%，包括入口与错误处理；覆盖率 include 所有 `src/**/*.{ts,tsx}`，逐文件门槛启用。没有执行分支的类型声明不产生运行指标。CSS、HTML、第三方依赖、编译生成文件与测试代码本身不属于可测生产 TS 源；测试清单核对源文件，防止遗漏未导入文件。

## 测试层次

UT 验证领域规则、持久事务、API 适配、Agent 行为、前端组件和桌面控制。Fastify inject 与实际 SQLite 验证 API 集成；Playwright 使用真实页面完成端到端用户流程。外部模型/WaveSurge 测试分别保留请求意图、脱敏响应、时间与来源。可控模型和网站用于确定性的并发、验证码、登录及故障用例，不能把它们报告成真实服务实测。

每阶段同时运行 typecheck、UT 及对应集成用例。新增代码使门槛不再满足时保留失败结果，修复后再接受阶段。最终执行完整覆盖与 E2E，从 compose 新建及重启验证部署，生成最终验收矩阵。

## 各阶段执行

阶段 0 保存模型及 Docker 网络探测。阶段 1 执行 A01/A02/C01/D01 基础路径；阶段 2 执行 C02–C04/X01–X06/M01；阶段 3 执行 W01–W03/S01–S03/R01；阶段 4 执行 B01–B04；阶段 5 执行 P01–P04；阶段 6 全量重跑并检查需求覆盖清单。

真实接口等待较长时，确定性集成用例与带来源的真实完成快照并行推进，新任务独立记录远端进度。真实搜索没有结束时不能把完成快照冒充该任务；不能用 HTTP 200 推导页面/证据或业务筛选成功。

## 最终验收产物

保留完整源文件覆盖率报告与逐文件明细、测试结果、浏览器截图/trace、模型/接口脱敏观测、compose 构建与健康结果、已知外部限制。演示包括直接筛选、执行期间连续发消息、Campaign 目标规划、多类型结果、人工接管与原任务续接、提示词更新/上下文调试、报告下载和重启恢复。
