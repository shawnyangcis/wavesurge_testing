# 独立 Review 的复核与修改判断

2026-10-10，Asia/Shanghai。复核对象：现有业务源码、运行中的 Docker 实例，以及 [原 review](../review-2026-10-10/review-report.md)。本轮先做分析，不修改业务实现、模型设置或任务范围，不启动新 WaveSurge 搜索，也不重启服务。

## 结论

报告总体可信，F01–F07、F09 对应的现象得到源码核对或本轮复现支持；F08 是有效的测试可复现性和验收证据问题，应修测试与验收表达，不能据此推导核心功能未实现。需要修改，但不需要推倒现有 Agent 架构。

之前将工程机制及覆盖率通过概括成“系统完成”，表述范围过满。准确结论应是：核心工作流已可运行，有真实 API/模型/浏览器的部分闭环证据，但仍有正确性、恢复和交付缺陷；原题完整混合条件及 20 人名单的业务验收尚未完成。100% 覆盖率不能替代需求正确性、视觉判断质量或新部署全链路验收。

## 逐项判断

| 发现 | 本轮复核 | 是否修改及理由 |
| --- | --- | --- |
| F01 账号重复计数 | 隔离复跑：同一个 Instagram URL，一条带 handle、一条缺 handle，生成两个 id，Campaign 错报 matched=2 | 必须先修。统一平台账号身份，规范 URL/handle 的等价形式；对子任务候选及 Campaign 汇总使用同一身份规则。对旧记录也需处理，不能只修新数据。 |
| F02 人工协助阻塞全部研究 | 隔离复跑：pending 协助存在时，不需要浏览器的新任务也没有 submit，仍 queued；源码 tick 入口直接退出 | 必须先修。人工接管暂停共享桌面的自动输入是正确的；阻断其它任务的 API 提交、轮询和无需浏览器的核验则不必要。应仅阻止争用桌面的阶段。 |
| F03 临时模型故障成为终态 unknown | 隔离复跑：首次 503 后结果 unknown、任务 partial；再次 wake 不调用 verifier，计数仍为 1 | 需要修。证据不足与执行失败必须区分。基础设施临时错误做有次数上限的重试，并提供明确的失败核验重试能力；保留 remoteId 和原候选，不重新提交搜索。 |
| F04 偏好没有影响选择 | 隔离复跑：count=1、budget=2，第一个人不满足偏好却被选中；第二个人未核验。Campaign 分配也没有偏好评分 | 需要修。optional 不作为淘汰条件是正确的，但既然工作流/UI 提供“优先、偏好”，必须在预算内参与排序。先满足硬条件和去重配额，再按有证据的偏好匹配选择。 |
| F05 筛选与 CSV 范围不一致 | 生产接口和浏览器均复核：全部 2 人，match 筛选 1 人；CSV 仍 2 人，含明确标为 unknown 的记录 | 需要修交互/契约。不是把 unknown 伪造成 match。应明确区分“导出当前筛选”和“导出全部核验”；默认导出当前已应用筛选，并共用筛选规则。 |
| F06 报告证据不完整 | 生产数据有 5 个带 assetId 的 evidence；HTML 没有图片或资产引用，也不输出原始证据文字；CSV 有引用 id，但无完整证据映射 | 需要修。输出 evidence id→来源、原文、采集时间、截图的可审计映射，基础字段判断也引用来源。独立 HTML 可内嵌截图；仅加入需要登录的资产 URL，仍不等于离开应用后可复核。 |
| F07 浏览器动作边界依赖提示词 | 复跑模拟 Page：执行器接受 localhost 导航和 password 字段填充；没有真实内网请求、真实凭据或外联 | 缺少执行约束成立，需修；尚不能声称真实攻击成功。导航限制到候选来源/最新观察中的合法公开链接，并拒绝内部地址和凭据；自动输入限研究用途，密码/验证码转人工，危险动作在执行层拒绝。 |
| F08 E2E 依赖历史数据 | 源码确认两项完成测试使用固定 id，测试自身不创建/导入相应对象；另有 fresh Compose 基础部署验证 | 需要改测试分层。历史快照回归可以保留并准确命名；补充从干净卷创建对象的核心/Campaign 工作流测试。不能说“没测试干净部署”，也不能说“已有干净卷业务全验收”。 |

## 需要校准的几个结论

1. **人工 pending 是否到期与全局阻塞是两件事。** 待用户登录可以保留请求，不必时间一到自动认定失败；关键是其它不占桌面的阶段继续推进。当前 pending 不自动到期是事实，但不是必须用自动取消才能解决的问题。
2. **原题 20 人没有完整验收，不等于必须伪造满额或放宽条件。** 此前真实 1/2 和受控 2/2 各自证明部分闭环、去重机制，不能证明眼镜、geek、KOC、自述等混合条件已准确筛完 20 人。应跑原题的实际链路，允许真实缺额，但逐项给出有证据的判定和缺口。
3. **远端预计 5 小时是服务估计，不是本地计算慢或保证交付时间。** 09:19 CST 只读核对时，review 新研究仍在 queued，本地 0 位已核验。建议把 expectedDurationHours、最近成功轮询时间和排队状态展示出来，减少“快速”承诺与实际体验的落差。
4. **国家探针没有构成新的自然语言 bug 证据。** 工具约定英文国家，明确“城市, 国家”格式已处理；中文、城市范围能否从自然语言正确转成国家/定性条件，要单独从用户输入验收，不能只用违反工具契约的底层参数下结论。
5. **现有 UT 有业务预期问题。** `tests/research.test.ts` 明确断言人工 pending 时其它任务的 submit 也不发生。这解释了为何 100% 路径覆盖仍会放过 F02。修复时应更新这些需求断言，而不是单纯再追求覆盖数字。

## 建议修复与验收顺序

第一批处理 F01/F02/F03/F07：账号规范化、桌面占用边界、临时故障恢复、执行权限。继续使用现有 ResearchEngine、verification session、Store 和 DesktopBroker，只加必要的身份函数、失败分类/重试记录和动作校验，不引入大型意图状态机。

第二批处理 F04/F05/F06/F09：有偏好时在预算内核验再选择；导出反映“已应用”的筛选条件（不能只读取尚未点击查询的表单值）；HTML/CSV 携带完整证据映射；表格正常渲染。

第三批补 F08 和原题业务验收：

- 可重复的受控集成/E2E 从新数据库创建任务，覆盖基础条件、混合定性条件、重叠身份、配额缺额、人工暂停与其它任务推进、503 后恢复、过滤导出和服务重启；测试记录明确标注 fixture。
- 保留实际 API 快照作为回归证据，避免硬编码历史 id 成为全套测试的隐含前置条件；实时 WaveSurge 测试另行记录服务状态和实际产出。
- 用独立、人工核对的证据样本验证眼镜、geek 风、KOC 与明确公开自述：包括正例、反例、证据不足和粉丝边界，逐条件核对 false match/no_match/unknown，尤其关注最终误纳入。
- 从普通自然语言开始跑核心原题与 Campaign：目标→澄清→版本修订→确认→召回→逐人核验→去重结果→可独立查看的文档。不要用测试提示要求特定内部工具名来替代需求理解验收。
- 修复后的全部生产 TS/TSX 仍执行逐文件行/分支 100% 门槛，集成及浏览器测试验证业务结论；覆盖率只是其中一个门槛。

本轮未做业务修复，当前缺陷仍存在。此文是修改判断与验收建议，不是新的“全部验收通过”声明。
