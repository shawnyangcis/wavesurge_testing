BF32 总报告缺逐人匹配说明总 HTML 直接交付每位入选者的逐条件状态、理由、标签、画像及来源，不要求读者自行推断帖子内容。完整来源可展开；分组说明范围、偏好、人数和缺额。总 CSV 仅导出最终入选名单。
CF26 粉丝行引用膨胀删除“全部非浏览器资料都是粉丝证据”的逻辑，仅引用相应本人事实和含该数值的资料/字段。原始帖子、媒体、截图仍完整保存；明确保存的 API 数值字段独立标明提供方和原捕获时间。
CF28 旧请求覆盖新查询请求序号只允许最新响应提交页面结果、错误和已应用筛选；切换任务或卸载作废旧响应。HTML/CSV 链接跟随最后成功的查询。
CF27 肯定标签误中否定标签UI 默认精确实际标签值；新增 tagMode=exact/contains，明确文字包含可能包括否定标签。Agent 查询支持相同模式，API 未指定模式时兼容已有包含行为。未知画像不成为正向标签。

CSV 原 14 列的顺序保留，追加 11 列，共 25 列。未知、不合格及合格备选仍保留在所属研究，不能通过删除记录或改变判断来统一人数。已分配其他 Campaign 类型的账号，在本组明确显示“本组未入选（已分配其他组）”。

新的真实 API 与自然语言验收

实际调用目标为 https://wavesurge.ai/api/v1，使用用户配置的 token、模型和生产任务执行代码。共 50 次 GET，均为 HTTP 200；29 次实际模型调用，无调用错误。没有使用伪造候选、判断或 Wave 返回。三个研究、一次全记录补标及一个交互式 Campaign 共产生 8 个后台任务、10 条结果、3 次综合交付。
