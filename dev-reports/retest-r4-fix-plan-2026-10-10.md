# R4 修复方案与验收计划

依据 R4 的 report.md、findings.md、structured-document-validation.md 和实际渲染/查询代码。七项均有可复现根因；F27 是字面包含模式的产品不足，其它六项是缺陷。修复保持 LLM 的目标理解、逐人判断、标签与原证据；代码只处理报告统计、来源归属、分配口径、引用范围和请求并发。

## 分阶段实施

| 阶段 | 问题与根因 | 实施 | 验收 |
|---|---|---|---|
| A | F30：用 task.matched（入选）显示合格。F31：工作汇总丢失来源任务；混算补标记录与研究名额 | 报告从实际记录计算核验/合格/入选、记录数和平台账号去重数。每条 HTML/CSV 保留结果 ID、来源任务/标题、分组及入选口径；多组保留全部组内记录并展示分组配额。补标进度用记录单位；筛选报告区分全量统计和展示子集 | 两合格选一；三组六记录对应两账号、五合格记录与三组入选记录；空名单、零合格；过滤后统计；CSV 标准解析并逐条匹配 HTML/保存数据 |
| B | F29：子报告/弹窗/查询沿用独立研究预选。F32：Campaign 总报告只输出来源，没有逐人说明 | 复用现有去重分配算法提供读时报告投影。Campaign 总/子 HTML、CSV、结果 API 和 Agent 查询统一使用 Campaign 当前分配；原研究预选保留在数据库及明确的审计字段。复用逐人条件/理由/标签/画像/证据渲染；总报告增加分组 CSV | 重叠候选跨组分配、只占一次配额；总/子/批次/CSV/结果弹窗/Agent 查询逐人入选一致；不修改原 judgments、标签、身份或预选数据；缺额与未知不补成推荐 |
| C | F26：粉丝行拼入全部非浏览器证据。F28：所有异步响应都可覆盖页面。F27：正负标签都被 includes 召回 | 引用仅限对应数值的本人事实及 Wave 资料/数值字段，全部其它证据仍保存；定向迁移已有冗余引用，保存旧版本且不远端重核验/重发报告。结果页只接收最新请求，任务切换/卸载作废旧请求。UI 默认精确标签值，并明确提供文字包含模式；CSV/HTML跟随成功查询 | 粉丝冗余引用缩减为实际数值来源，值和结论不变；延迟真实响应到新筛选成功后返回及乱序查询；失败/卸载/任务切换；“戴眼镜”不返回“不戴眼镜”，明确包含模式可返回，未知值不当正例 |

## 验证层级与完成标准

1. 先写针对七项的失败回归，证明原行为确实不符合期望；再分阶段修复并执行相关集成测试。
2. 对 R4 实际已存数据制作私有只读快照，在独立实例验证真实来源的正向、六条跨组补标和 Campaign 文档；不写回复测3592，也不使用旧截图冒充新访问。
3. 用真实模型和实际 Wave token 执行新的自然语言研究/分组及 Campaign；实际打开 HTML、下载并解析 CSV、逐条比对统计/归属/分配/理由。重新补标只复用已保存证据。
4. 真实浏览器延迟实际 HTTP 响应验证 F28；不伪造返回内容。检查1440/768/375报告与过滤/导出。
5. 完整类型检查、构建、测试、既有 Docker 浏览器回归；最后部署3000并核对源码、保存数据、历史通知及普通重启。覆盖率和HTTP200仅作辅助，不能代替文档语义及实际模型/API验证。

修复范围是报告、分配投影、证据引用与结果查询链路及对应测试。不会把合格备选改成不合格、删除跨组记录或修改 LLM 业务条件以凑配额。真实平台登录和原题20位全部条件正例，仍依赖实际来源与人工凭据，不能用受控测试宣称已证明。
